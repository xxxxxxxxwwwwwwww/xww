问题1：缺失值处理

00:00
简单

编写一个程序，使用Pandas处理DataFrame中的缺失值。

输入：

一个包含缺失值的DataFrame

输出：

处理后的DataFrame，其中缺失值已被适当处理

要求：

  • 识别并统计缺失值
  • 使用合适的方法填充缺失值（如均值、中位数或众数）
  • 返回处理后的DataFrame

答案解析

解题思路

1. 使用Pandas的isnull()和sum()方法识别并统计缺失值

2. 根据数据类型选择合适的填充方法：数值型数据使用均值或中位数，分类型数据使用众数

3. 使用fillna()方法填充缺失值

代码示例

import pandas as pd
import numpy as np

# 创建示例数据
data = {
    'A': [1, 2, np.nan, 4, 5],
    'B': [np.nan, 2, 3, 4, np.nan],
    'C': ['x', 'y', 'z', np.nan, 'x']
}
df = pd.DataFrame(data)

# 识别缺失值
print("缺失值统计:")
print(df.isnull().sum())

# 处理缺失值
df['A'] = df['A'].fillna(df['A'].mean())
df['B'] = df['B'].fillna(df['B'].median())
df['C'] = df['C'].fillna(df['C'].mode()[0])

print("\n处理后的数据:")
print(df)

模块1：数据库基础概念（8学时）

数据库基本概念

数据库（Database，简称DB）是长期存储在计算机内、有组织、可共享的大量数据的集合。数据库中的数据按一定的数据模型组织、描述和存储，具有较小的冗余度、较高的数据独立性和易扩展性，并可为各种用户共享。理解数据库的基本概念是学习数据库技术的基础。

📌 核心概念详解
  • • 数据（Data）：描述事物的符号记录，是数据库中存储的基本对象。数据不仅包括数字，还包括文本、图像、音频、视频等各种形式。
  • • 数据库（DB）：长期存储在计算机内、有组织、可共享的数据集合。数据库具有永久存储、有组织、可共享三个基本特点。
  • • 数据库管理系统（DBMS）：位于用户与操作系统之间的一层数据管理软件，用于科学地组织和存储数据、高效地获取和维护数据。
  • • 数据库系统（DBS）：在计算机系统中引入数据库后的系统，由数据库、数据库管理系统、应用程序和数据库管理员（DBA）组成的存储、管理、处理和维护数据的系统。
💡 数据库的主要特点
  • • 数据结构化：数据库中的数据按一定的数据模型组织
  • • 数据共享性高：多用户、多应用可同时访问数据
  • • 数据独立性强：数据与程序分离，互不影响
  • • 数据由DBMS统一管理：提供安全性、完整性、并发控制

数据库发展历史

数据库技术是应数据管理任务的需要而产生的。数据管理是指对数据进行分类、组织、编码、存储、检索和维护，是数据处理的中心问题。随着计算机硬件和软件的发展，数据管理经历了人工管理、文件系统、数据库系统三个阶段。

📅 第一阶段：人工管理阶段（1950年代）

特点：数据不保存、不共享，数据与程序不独立。数据由程序直接管理，一组数据对应一个程序。

  • • 数据不保存在计算机中
  • • 没有专门的数据管理软件
  • • 数据不共享，冗余度极大
  • • 数据完全依赖于程序
📅 第二阶段：文件系统阶段（1960年代）

特点：数据可长期保存，由文件系统管理，但数据独立性差，共享性差。

  • • 数据以文件形式长期保存
  • • 由文件系统管理数据
  • • 数据共享性差，冗余度大
  • • 数据独立性差
📅 第三阶段：数据库系统阶段（1970年代至今）

特点：数据结构化，共享性高，独立性强，由DBMS统一管理。

  • • 数据结构化，整体结构化
  • • 数据共享性高，冗余度小
  • • 数据独立性高
  • • 数据由DBMS统一管理和控制

数据模型

数据模型是数据库系统的核心和基础，是对现实世界数据特征的抽象。数据模型应满足三方面要求：能比较真实地模拟现实世界、容易为人所理解、便于在计算机上实现。根据应用目的不同，数据模型分为概念模型、逻辑模型和物理模型三类。

📊 三层模型结构

概念模型（信息模型）

按用户观点对数据建模，主要用于数据库设计。常用E-R图表示，独立于具体DBMS。

逻辑模型

按计算机观点对数据建模，包括层次模型、网状模型、关系模型等。直接与DBMS相关。

物理模型

描述数据在存储介质上的组织方式，涉及索引、存储结构等底层细节。

🔗 主要逻辑模型对比
模型 结构 特点
层次模型 树形结构 结构简单，但无法表示多对多
网状模型 图结构 可表示复杂关系，但结构复杂
关系模型 二维表 简单灵活，数学基础坚实

数据库系统结构

数据库系统采用三级模式结构，这是数据库管理系统内部的系统结构。三级模式结构提供了数据的抽象机制，实现了数据的独立性，使得用户能够逻辑地、抽象地处理数据，而不必关心数据在计算机中的具体表示和存储方式。

🏗️ 三级模式结构详解

外模式（用户模式）

数据库用户能够看见和使用的局部数据的逻辑结构和特征的描述。每个用户只能看到外模式中定义的数据，是保证数据库安全性的一个有力措施。

模式（逻辑模式/概念模式）

数据库中全体数据的逻辑结构和特征的描述，是所有用户的公共数据视图。一个数据库只有一个模式，它定义了数据的逻辑结构、数据之间的联系、数据的安全性要求等。

内模式（存储模式）

数据物理结构和存储方式的描述，是数据在数据库内部的表示方式。一个数据库只有一个内模式，包括记录的存储方式、索引的组织方式、数据是否压缩等。

🔄 两级映像与数据独立性

外模式/模式映像

保证数据的逻辑独立性。当模式改变时，只需修改此映像，使外模式保持不变，应用程序也不用修改。

模式/内模式映像

保证数据的物理独立性。当数据库的存储结构改变时，只需修改此映像，使模式保持不变，应用程序也不用修改。

数据库管理系统（DBMS）

数据库管理系统是数据库系统的核心软件，位于用户与操作系统之间。DBMS的主要目标是使数据作为一种可管理的资源来处理，实现数据的集中管理、共享使用，减少数据冗余，保证数据的一致性和完整性。

⚙️ 主要功能

数据定义（DDL）

定义数据库结构，包括模式、外模式、内模式的定义

数据操纵（DML）

实现对数据的增、删、改、查等基本操作

数据控制（DCL）

数据安全性、完整性、并发控制、恢复

数据库维护

数据导入导出、重组、性能监控等

🛡️ 数据控制功能详解
  • • 数据安全性保护：防止不合法使用造成数据泄露和破坏
  • • 数据完整性检查：保证数据的正确性、有效性和相容性
  • • 并发控制：防止多用户并发访问时数据不一致
  • • 数据库恢复：系统故障后恢复到一致状态

主流数据库产品

了解主流数据库产品有助于在实际项目中选择合适的数据库系统。不同的数据库产品在性能、功能、应用场景等方面各有特点。

模块2：关系数据库理论（10学时）

关系模型基本概念

关系模型是建立在严格的数学概念基础上的数据模型。在关系模型中，现实世界的实体以及实体间的各种联系均用关系来表示。关系模型由关系数据结构、关系操作集合和关系完整性约束三部分组成，是目前应用最广泛的数据模型。

📊 关系模型核心术语
  • • 关系（Relation）：一个关系对应通常说的一张表，每个关系有一个关系名。关系是笛卡尔积的有限子集。
  • • 元组（Tuple）：表中的一行即为一个元组，表示一个具体的实体或联系。
  • • 属性（Attribute）：表中的一列即为一个属性，每个属性有一个属性名。
  • • 码（Key）：唯一标识元组的属性或属性组，包括候选码、主码、外码等。
  • • 域（Domain）：属性的取值范围，是一组具有相同数据类型的值的集合。
🔗 关系的形式化定义

设D1, D2, ..., Dn为域，则D1×D2×...×Dn的子集称为在域D1, D2, ..., Dn上的关系，表示为R(D1, D2, ..., Dn)，其中R为关系名，n为关系的目或度。

关系 = 表

元组 = 行

属性 = 列

域 = 列的取值范围

关系代数

关系代数是一种抽象的查询语言，它用对关系的运算来表达查询。关系代数的运算对象是关系，运算结果也是关系。关系代数运算分为传统集合运算和专门的关系运算两类。

📐 传统集合运算

并（Union）：R ∪ S

返回R和S中所有元组，去除重复

差（Difference）：R - S

返回在R中但不在S中的元组

交（Intersection）：R ∩ S

返回同时在R和S中的元组

笛卡尔积：R × S

返回R和S所有元组的组合

🔧 专门的关系运算

选择（Selection）：σF(R)

从R中选择满足条件F的元组

投影（Projection）：πA(R)

从R中选择若干属性列组成新关系

连接（Join）：R ⋈ S

从R和S的笛卡尔积中选择满足条件的元组

除（Division）：R ÷ S

返回R中与S中所有元组都匹配的元组

范式理论

范式是关系数据库规范化的标准，用于消除数据冗余和更新异常。满足最低要求的叫第一范式（1NF），在第一范式中满足进一步要求的为第二范式（2NF），其余以此类推。范式越高，规范化程度越高，但查询效率可能降低。

📐 第一范式（1NF）

定义：关系的每个属性都是不可再分的数据项。

要求：每个列都是原子的，不能包含数组、集合等复合值。

例如：地址不能拆分为省、市、区（违反1NF）

应拆分为：省份、城市、区县三个独立字段

📐 第二范式（2NF）

定义：在1NF基础上，非主属性完全函数依赖于码。

要求：消除非主属性对码的部分依赖。

例如：(学号,课程号)→成绩，(学号,课程号)→学生姓名

学生姓名只依赖学号，存在部分依赖（违反2NF）

应拆分为：学生表(学号,姓名)、成绩表(学号,课程号,成绩)

📐 第三范式（3NF）

定义：在2NF基础上，非主属性不传递依赖于码。

要求：消除非主属性对码的传递依赖。

例如：学号→系名→系主任

系主任传递依赖于学号（违反3NF）

应拆分为：学生表(学号,系名)、系表(系名,系主任)

📐 BCNF（Boyce-Codd范式）

定义：在3NF基础上，主属性不部分依赖于码，也不传递依赖于码。

要求：每个决定因素都包含候选码。

BCNF是修正的第三范式，扩充了3NF的定义

比3NF更严格，消除了主属性对码的部分和传递依赖

函数依赖

函数依赖是关系模式中属性之间的一种约束关系，是规范化理论的依据。设R(U)是属性集U上的关系模式，X、Y是U的子集。若对于R(U)的任意一个可能的关系r，r中不可能存在两个元组在X上的属性值相等而在Y上的属性值不等，则称X函数确定Y，或Y函数依赖于X，记作X→Y。

📊 函数依赖类型

完全函数依赖

Y完全依赖于X，不依赖X的任何真子集。记作X ⟶ Y

部分函数依赖

Y依赖于X，但也依赖于X的真子集。记作X ↛ Y

传递函数依赖

X→Y，Y→Z，且Y不依赖于X，则X传递依赖于Z

🔧 Armstrong公理系统

• 自反律：若Y⊆X，则X→Y

• 增广律：若X→Y，则XZ→YZ

• 传递律：若X→Y且Y→Z，则X→Z

导出规则：

合并规则、分解规则、伪传递规则

完整性约束

完整性约束是保证数据库中数据正确性和相容性的机制。关系模型的完整性约束包括实体完整性、参照完整性和用户定义的完整性三类，前两者是关系模型必须满足的完整性约束条件。

🔐 实体完整性

若属性（或属性组）A是基本关系R的主属性，则A不能取空值。

主键是唯一标识实体的属性，空值意味着无法标识实体，违反了实体完整性。

CREATE TABLE students (

id INT PRIMARY KEY, -- 主键不能为空

name VARCHAR(50)

);

🔗 参照完整性

若属性（或属性组）F是基本关系R的外码，它与基本关系S的主码K相对应，则对于R中每个元组在F上的值必须：

  • • 或者取空值（NULL）
  • • 或者等于S中某个元组的主码值

CREATE TABLE orders (

id INT PRIMARY KEY,

user_id INT,

FOREIGN KEY (user_id) REFERENCES users(id)

);

⚙️ 用户定义的完整性

针对某一具体关系数据库的约束条件，反映具体应用领域的数据要求。

CREATE TABLE products (

id INT PRIMARY KEY,

price DECIMAL(10,2) CHECK (price > 0),

stock INT DEFAULT 0,

name VARCHAR(100) NOT NULL

);

规范化过程

规范化是将一个低一级范式的关系模式通过模式分解转换为若干个高一级范式的关系模式的集合的过程。规范化实质上是概念的单一化，即一个关系描述一个概念。

📊 规范化步骤
1NF 消除非原子属性 → 属性不可再分
2NF 消除部分依赖 → 完全函数依赖
3NF 消除传递依赖 → 直接依赖
BCNF 消除主属性依赖 → 决定因素含码
⚠️ 规范化与性能权衡
  • • 优点：减少数据冗余，消除更新异常
  • • 缺点：增加连接操作，可能降低查询效率
  • • 建议：一般达到3NF即可，根据实际需求权衡

模块3：SQL语言（12学时）

SQL概述

SQL（Structured Query Language，结构化查询语言）是关系数据库的标准语言，是一种非过程化语言。SQL语言简洁、易学易用，功能强大，可以完成数据定义、数据操纵、数据控制等核心功能。SQL已成为国际标准，各大数据库厂商都支持SQL标准。

📝 SQL语言分类

DDL（数据定义语言）

CREATE, ALTER, DROP, TRUNCATE - 定义和修改数据库结构

DML（数据操纵语言）

SELECT, INSERT, UPDATE, DELETE - 查询和修改数据

DCL（数据控制语言）

GRANT, REVOKE - 控制数据访问权限

TCL（事务控制语言）

COMMIT, ROLLBACK, SAVEPOINT - 控制事务

💡 SQL语言特点
  • • 非过程化：只需指定"做什么"，不需指定"怎么做"
  • • 面向集合：操作对象和结果都是元组的集合
  • • 统一性：独立和嵌入式两种使用方式语法一致
  • • 简洁性：语法简单，核心动词只有9个

DDL数据定义语言

DDL用于定义和修改数据库结构，包括数据库、表、索引、视图等对象的创建、修改和删除。DDL操作会自动提交事务，影响数据库的结构而非数据内容。

-- ========== 数据库操作 ==========
CREATE DATABASE school CHARACTER SET utf8mb4;
DROP DATABASE IF EXISTS school;
USE school;

-- ========== 表操作 ==========
-- 创建表
CREATE TABLE students (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL COMMENT '学生姓名',
    age INT CHECK (age >= 0 AND age <= 150),
    email VARCHAR(100) UNIQUE,
    gender ENUM('男', '女') DEFAULT '男',
    department_id INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_name (name),
    FOREIGN KEY (department_id) REFERENCES departments(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 修改表结构
ALTER TABLE students ADD COLUMN phone VARCHAR(20);
ALTER TABLE students DROP COLUMN phone;
ALTER TABLE students MODIFY COLUMN name VARCHAR(100);
ALTER TABLE students CHANGE COLUMN name student_name VARCHAR(100);
ALTER TABLE students ADD INDEX idx_age (age);

-- 删除表
DROP TABLE IF EXISTS students;
TRUNCATE TABLE students;  -- 清空表，保留结构

DML数据查询（SELECT）

SELECT是SQL中最常用的语句，用于从数据库中检索数据。SELECT语句功能强大，支持条件过滤、排序、分组、聚合、连接、子查询等复杂操作。

-- ========== 基本查询 ==========
SELECT * FROM students;
SELECT name, age FROM students;
SELECT DISTINCT department FROM students;

-- ========== 条件查询 ==========
SELECT * FROM students WHERE age > 18;
SELECT * FROM students WHERE age BETWEEN 18 AND 25;
SELECT * FROM students WHERE name LIKE '张%';
SELECT * FROM students WHERE department IN ('计算机', '数学');
SELECT * FROM students WHERE age > 18 AND gender = '女';

-- ========== 排序与限制 ==========
SELECT * FROM students ORDER BY age DESC, name ASC;
SELECT * FROM students LIMIT 10 OFFSET 20;  -- 分页

-- ========== 聚合函数 ==========
SELECT COUNT(*) as total FROM students;
SELECT AVG(age) as avg_age, MAX(age), MIN(age), SUM(credit);
SELECT department, COUNT(*) as count 
FROM students GROUP BY department HAVING count > 5;

-- ========== 多表连接 ==========
-- 内连接
SELECT s.name, c.course_name
FROM students s
INNER JOIN enrollments e ON s.id = e.student_id
INNER JOIN courses c ON e.course_id = c.id;

-- 左外连接
SELECT s.name, e.score
FROM students s
LEFT JOIN enrollments e ON s.id = e.student_id;

-- 自连接
SELECT e1.name, e2.name as manager
FROM employees e1
LEFT JOIN employees e2 ON e1.manager_id = e2.id;

子查询与高级查询

子查询是嵌套在其他查询中的查询，可以在WHERE、FROM、SELECT等子句中使用。子查询使得复杂的查询逻辑更加清晰，是SQL高级应用的重要内容。

-- ========== 标量子查询 ==========
SELECT * FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);

-- ========== IN子查询 ==========
SELECT * FROM students
WHERE department_id IN (SELECT id FROM departments WHERE name = '计算机');

-- ========== EXISTS子查询 ==========
SELECT * FROM students s
WHERE EXISTS (SELECT 1 FROM enrollments e WHERE e.student_id = s.id);

-- ========== FROM子句子查询（派生表）==========
SELECT dept_name, avg_salary
FROM (SELECT d.name as dept_name, AVG(e.salary) as avg_salary
      FROM departments d
      JOIN employees e ON d.id = e.department_id
      GROUP BY d.id, d.name) AS dept_stats
WHERE avg_salary > 10000;

-- ========== 相关子查询 ==========
SELECT s.name, s.score,
       (SELECT AVG(score) FROM enrollments WHERE course_id = s.course_id) as avg_score
FROM enrollments s;

-- ========== UNION联合查询 ==========
SELECT name FROM students
UNION
SELECT name FROM teachers;

-- ========== CASE表达式 ==========
SELECT name,
       CASE 
         WHEN score >= 90 THEN '优秀'
         WHEN score >= 80 THEN '良好'
         WHEN score >= 60 THEN '及格'
         ELSE '不及格'
       END as grade
FROM enrollments;

DML数据操作

DML包括INSERT、UPDATE、DELETE三种操作，用于对数据库中的数据进行增删改。这些操作会改变数据内容，需要配合事务使用以保证数据一致性。

-- ========== INSERT插入数据 ==========
-- 单行插入
INSERT INTO students (name, age, email)
VALUES ('张三', 20, 'zhangsan@example.com');

-- 多行插入
INSERT INTO students (name, age) VALUES
('李四', 22),
('王五', 21),
('赵六', 23);

-- 从查询结果插入
INSERT INTO students_backup
SELECT * FROM students WHERE age > 20;

-- ========== UPDATE更新数据 ==========
-- 简单更新
UPDATE students SET age = 21 WHERE name = '张三';

-- 多字段更新
UPDATE students 
SET age = 21, email = 'new@example.com', updated_at = NOW()
WHERE id = 1;

-- 带子查询的更新
UPDATE employees e
SET salary = salary * 1.1
WHERE department_id = (SELECT id FROM departments WHERE name = '研发');

-- ========== DELETE删除数据 ==========
-- 条件删除
DELETE FROM students WHERE age < 18;

-- 带子查询的删除
DELETE FROM students
WHERE department_id IN (SELECT id FROM departments WHERE status = 'closed');

-- 清空表（DDL，更快，重置自增）
TRUNCATE TABLE students;

索引与视图

索引是提高查询效率的重要手段，视图是虚拟表，可以简化复杂查询。合理使用索引和视图是数据库优化的重要手段。

📊 索引操作

-- 创建普通索引

CREATE INDEX idx_name ON students(name);

-- 创建唯一索引

CREATE UNIQUE INDEX idx_email ON students(email);

-- 创建复合索引

CREATE INDEX idx_dept_age ON students(department_id, age);

-- 创建全文索引

CREATE FULLTEXT INDEX idx_content ON articles(content);

-- 删除索引

DROP INDEX idx_name ON students;

👁️ 视图操作

-- 创建视图

CREATE VIEW v_student_scores AS

SELECT s.name, c.course_name, e.score

FROM students s

JOIN enrollments e ON s.id = e.student_id

JOIN courses c ON e.course_id = c.id;

-- 使用视图

SELECT * FROM v_student_scores WHERE score > 80;

-- 删除视图

DROP VIEW IF EXISTS v_student_scores;

查询优化技巧

SQL查询优化是数据库性能优化的核心。掌握查询优化技巧可以显著提高系统性能，减少资源消耗。

⚡ 优化原则
  • • 避免SELECT *：只查询需要的列
  • • 合理使用索引：WHERE、JOIN、ORDER BY字段建索引
  • • 避免在索引列上使用函数：会导致索引失效
  • • 避免隐式类型转换：保持类型一致
  • • 使用EXISTS代替IN：大数据量时更高效
  • • 使用LIMIT限制结果集：减少数据传输
📊 执行计划分析

-- 查看执行计划

EXPLAIN SELECT * FROM students WHERE name = '张三';

-- 查看详细执行计划

EXPLAIN ANALYZE SELECT * FROM students s

JOIN enrollments e ON s.id = e.student_id;

重点关注：type（访问类型）、key（使用索引）、rows（扫描行数）、Extra（额外信息）

模块4：数据库设计（12学时）

数据库设计概述

数据库设计是指对于一个给定的应用环境，构造最优的数据库模式，建立数据库及其应用系统，使之能够有效地存储数据，满足各种用户的应用需求。数据库设计是数据库应用系统开发的核心环节，设计质量直接影响系统的性能和可维护性。

📋 设计步骤
1 需求分析：收集用户需求，确定系统边界
2 概念设计：设计E-R模型，描述实体和联系
3 逻辑设计：将E-R图转换为关系模式
4 物理设计：选择存储结构和存取方法
5 实施与维护：创建数据库，测试和优化
💡 设计原则
  • • 避免数据冗余：减少重复存储，节省空间
  • • 保证数据一致性：避免数据冲突和矛盾
  • • 合理设置约束：主键、外键、唯一约束等
  • • 考虑性能优化：索引、分区、分表等

实体-关系模型（E-R模型）

E-R模型是概念模型的一种，由Peter Chen于1976年提出。E-R模型用图形方式描述现实世界的实体及其联系，独立于具体的DBMS，是数据库概念设计的主要工具。E-R图简单直观，易于理解和交流。

📊 基本要素

实体（Entity）

客观存在并可相互区分的事物。用矩形表示，如"学生"、"课程"。

属性（Attribute）

实体所具有的某一特性。用椭圆表示，如"学号"、"姓名"。

联系（Relationship）

实体之间的关联。用菱形表示，如"选课"、"授课"。

🔗 联系类型

1:1

一对一

如：夫妻关系

1:N

一对多

如：班级-学生

M:N

多对多

如：学生-课程

概念设计

概念设计阶段的目标是产生反映用户信息需求的数据库概念结构，即概念模式。概念结构独立于数据库逻辑结构，独立于具体的DBMS，是各种数据模型的共同基础。

📐 E-R图设计方法
  • • 自顶向下：先定义全局概念结构，再逐步细化
  • • 自底向上：先定义局部概念结构，再集成全局
  • • 逐步扩张：先定义核心概念，再逐步扩展
  • • 混合策略：结合以上方法
🔧 E-R图绘制示例

【学生】--(选课)--【课程】

| |

学号,姓名 课程号,课程名

| |

+----成绩------+

学生与课程是多对多关系，选课联系有成绩属性

逻辑设计

逻辑设计阶段将概念结构转换为某个DBMS所支持的数据模型，并对其进行优化。对于关系数据库，主要是将E-R图转换为关系模式，并进行规范化处理。

📊 E-R图转关系模式规则

实体转换

每个实体转换为一个关系模式，实体的属性即为关系的属性，实体的码即为关系的码。

1:1联系转换

可以合并到任一实体中，或单独建立一个关系。

1:N联系转换

将"1"端的主码加入到"N"端作为外码。

M:N联系转换

建立一个新的关系，包含两端实体的主码和联系属性。

物理设计

物理设计阶段为逻辑数据模型选取一个最适合应用环境的物理结构，包括存储结构和存取方法。物理设计依赖于给定的DBMS和硬件环境，目标是提高数据库的性能。

💾 存储结构设计
  • • 确定数据存放位置：热数据、冷数据分离
  • • 确定系统配置：内存、缓冲区大小等
  • • 选择存储引擎：InnoDB、MyISAM等
⚡ 存取方法设计
  • • 索引设计：B+树索引、哈希索引、全文索引
  • • 聚簇设计：按物理顺序存储数据
  • • 分区设计：水平分区、垂直分区

数据库设计实践

通过实际案例学习数据库设计的完整流程。以学生选课系统为例，展示从需求分析到物理设计的全过程。

-- ========== 学生选课系统数据库设计 ==========

-- 学生表
CREATE TABLE students (
    student_id VARCHAR(20) PRIMARY KEY COMMENT '学号',
    name VARCHAR(50) NOT NULL COMMENT '姓名',
    gender ENUM('男', '女') DEFAULT '男' COMMENT '性别',
    birth_date DATE COMMENT '出生日期',
    department_id INT COMMENT '院系ID',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_name (name),
    INDEX idx_department (department_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 课程表
CREATE TABLE courses (
    course_id VARCHAR(20) PRIMARY KEY COMMENT '课程号',
    course_name VARCHAR(100) NOT NULL COMMENT '课程名',
    credit DECIMAL(3,1) NOT NULL COMMENT '学分',
    teacher_id INT COMMENT '教师ID',
    INDEX idx_teacher (teacher_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 选课表（多对多关系中间表）
CREATE TABLE enrollments (
    id INT PRIMARY KEY AUTO_INCREMENT,
    student_id VARCHAR(20) NOT NULL,
    course_id VARCHAR(20) NOT NULL,
    score DECIMAL(5,2) COMMENT '成绩',
    enroll_date DATE DEFAULT (CURRENT_DATE),
    UNIQUE KEY uk_student_course (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (course_id) REFERENCES courses(course_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

模块5：数据库管理（12学时）

事务管理

事务是用户定义的一个数据库操作序列，这些操作要么全做，要么全不做，是一个不可分割的工作单位。事务是数据库恢复和并发控制的基本单位。事务具有ACID四个特性：原子性、一致性、隔离性、持久性。

🔐 ACID特性

原子性（Atomicity）

事务中的操作要么全部完成，要么全部不完成，不会结束在中间某个环节。

一致性（Consistency）

事务必须使数据库从一个一致性状态变换到另一个一致性状态。

隔离性（Isolation）

一个事务的执行不能被其他事务干扰，各并发事务之间相互隔离。

持久性（Durability）

一个事务一旦提交，它对数据库中数据的改变就是永久性的。

📊 事务控制语句

-- 开始事务

START TRANSACTION;

BEGIN;

-- 提交事务

COMMIT;

-- 回滚事务

ROLLBACK;

-- 设置保存点

SAVEPOINT savepoint_name;

-- 回滚到保存点

ROLLBACK TO savepoint_name;

并发控制

当多个用户并发访问数据库时，可能会产生多个事务同时存取同一数据的情况。如果不加以控制，可能会存取和存储不正确的数据，破坏数据库的一致性。并发控制的主要技术是封锁。

🔒 封锁类型

共享锁（S锁，Shared Lock）

用于读操作，多个事务可同时获得同一数据对象的S锁。

排他锁（X锁，Exclusive Lock）

用于写操作，一个事务获得X锁后，其他事务不能再获得任何锁。

⚠️ 并发问题
  • • 丢失修改：两事务同时修改同一数据，一个覆盖另一个
  • • 不可重复读：同一事务两次读取同一数据结果不同
  • • 读"脏"数据：读取了未提交事务修改的数据
  • • 幻读：同一查询返回不同行数
📊 隔离级别
READ UNCOMMITTED 可能脏读
READ COMMITTED 避免脏读
REPEATABLE READ 避免不可重复读
SERIALIZABLE 避免幻读

数据库恢复技术

数据库恢复是指将数据库从错误状态恢复到某一已知的正确状态（一致性状态）。恢复技术是衡量系统优劣的重要指标，常用的恢复技术有日志文件、数据转储等。

📋 恢复技术

日志文件（Log File）

记录事务对数据库的更新操作，包括事务ID、操作类型、更新前后数据等。

数据转储（Dump）

定期将数据库复制到磁带或另一个磁盘上，包括静态转储和动态转储。

检查点（Checkpoint）

定期在日志文件中设置检查点，恢复时只需从最近的检查点开始。

🔧 恢复策略
  • • 事务故障恢复：撤销（UNDO）未完成事务
  • • 系统故障恢复：重做（REDO）已提交事务，撤销未完成事务
  • • 介质故障恢复：重装数据库备份，重做日志

数据备份与恢复

数据备份是防止数据丢失的重要手段，是数据库管理员的日常工作之一。合理的备份策略可以在数据丢失时快速恢复数据，保证业务连续性。

💾 备份类型

完全备份

备份整个数据库，恢复时只需一个备份文件，但备份时间长、占用空间大。

增量备份

只备份自上次备份后变化的数据，备份速度快，但恢复时需要多个备份文件。

差异备份

备份自上次完全备份后变化的数据，介于完全备份和增量备份之间。

🔧 MySQL备份命令

# 完全备份

mysqldump -u root -p school > backup.sql

# 备份特定表

mysqldump -u root -p school students > students.sql

# 恢复数据

mysql -u root -p school < backup.sql

# 二进制日志备份

mysqlbinlog mysql-bin.000001 | mysql -u root -p

PREPARE stmt FROM 'SELECT * FROM users WHERE name = ?';

参数化查询与安全

SQL注入是最常见的数据库安全漏洞之一，攻击者通过构造恶意输入来执行非预期的SQL语句。参数化查询（预编译语句）是防止SQL注入的最有效方法，它将SQL语句和数据分离，确保用户输入不会被解释为SQL代码。

⚠️ SQL注入示例

# 危险！存在SQL注入漏洞

username = "admin' OR '1'='1"

sql = f"SELECT * FROM users WHERE name='{username}'"

# 实际执行：SELECT * FROM users WHERE name='admin' OR '1'='1'

数据库性能优化

数据库性能优化是应用开发中的重要环节。优化需要从多个层面入手：SQL语句优化、索引设计、数据库配置、应用层缓存等。掌握性能优化技术可以显著提升系统响应速度和并发处理能力。

⚡ 优化策略
  • • SQL优化：避免SELECT *，使用合适的索引
  • • 批量操作：批量插入、批量更新减少交互次数
  • • 延迟加载：按需加载数据，减少不必要查询
  • • 缓存策略：使用Redis等缓存热点数据
  • • 读写分离：主库写入，从库读取
  • • 分库分表：水平拆分处理大数据量
🔧 批量操作示例

# 批量插入（高效）

data = [('张三', 20), ('李四', 22), ('王五', 21)]

sql = "INSERT INTO students (name, age) VALUES (%s, %s)"

cursor.executemany(sql, data)

conn.commit()

# 单条插入（低效）

for name, age in data:

class StudentManager:

def __init__(self, db_config):

def add_student(self, name, age, dept_id):
