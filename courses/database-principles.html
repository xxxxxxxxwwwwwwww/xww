问题1：缺失值处理

00:00
简单

编写一个程序，使用Pandas处理DataFrame中的缺失值。

输入：

一个包含缺失值的DataFrame

输出：

处理后的DataFrame，其中缺失值已被适当处理

要求：

  • 识别并统计缺失值
  • 使用合适的方法填充缺失值（如均值、中位数或众数）
  • 返回处理后的DataFrame

答案解析

解题思路

1. 使用Pandas的isnull()和sum()方法识别并统计缺失值

2. 根据数据类型选择合适的填充方法：数值型数据使用均值或中位数，分类型数据使用众数

3. 使用fillna()方法填充缺失值

代码示例

import pandas as pd
import numpy as np

# 创建示例数据
data = {
    'A': [1, 2, np.nan, 4, 5],
    'B': [np.nan, 2, 3, 4, np.nan],
    'C': ['x', 'y', 'z', np.nan, 'x']
}
df = pd.DataFrame(data)

# 识别缺失值
print("缺失值统计:")
print(df.isnull().sum())

# 处理缺失值
df['A'] = df['A'].fillna(df['A'].mean())
df['B'] = df['B'].fillna(df['B'].median())
df['C'] = df['C'].fillna(df['C'].mode()[0])

print("\n处理后的数据:")
print(df)

模块1：数据库基础知识（8学时）

数据库基本概念

数据库（Database）是长期存储在计算机内、有组织、可共享的数据集合。数据库具有以下特点：数据结构化、数据共享性高、数据独立性强、数据由DBMS统一管理和控制。

📌 核心概念
  • 数据（Data）：描述事物的符号记录
  • 数据库（DB）：长期存储的数据集合
  • 数据库管理系统（DBMS）：管理数据库的软件
  • 数据库系统（DBS）：DB+DBMS+应用程序+用户
💡 数据库的发展历程

人工管理阶段 → 文件系统阶段 → 数据库系统阶段

数据模型

数据模型是数据库系统中用于描述数据结构和数据间联系的工具，是数据库设计的基础。

📊 三层模型结构
  • 概念模型：按用户观点建模（E-R图）
  • 逻辑模型：按计算机观点建模（层次、网状、关系）
  • 物理模型：数据在存储介质上的组织方式
🔗 关系模型特点

建立在严格的数学概念基础上，概念单一，实体和联系都用关系表示，存取路径对用户透明。

数据库系统结构

数据库系统采用三级模式结构，提供了数据的抽象和独立性。

🏗️ 三级模式结构
  • 外模式（用户模式）：用户的数据视图
  • 模式（逻辑模式）：全体数据的逻辑结构
  • 内模式（存储模式）：数据的物理存储方式
🔄 两级映像
  • 外模式/模式映像：保证逻辑独立性
  • 模式/内模式映像：保证物理独立性

数据库管理系统

DBMS是位于用户与操作系统之间的一层数据管理软件，为用户或应用程序提供访问数据库的方法。

⚙️ 主要功能
  • 数据定义功能（DDL）
  • 数据操纵功能（DML）
  • 数据控制功能（DCL）
  • 数据库的建立和维护功能
🛡️ 数据控制功能
  • 数据安全性保护
  • 数据完整性检查
  • 并发控制
  • 数据库恢复

模块2：SQL语言基础（12学时）

SQL简介

SQL（Structured Query Language）是结构化查询语言，是关系数据库的标准语言。

📝 SQL语言分类
  • DDL：数据定义语言（CREATE, ALTER, DROP）
  • DML：数据操纵语言（SELECT, INSERT, UPDATE, DELETE）
  • DCL：数据控制语言（GRANT, REVOKE）
  • TCL：事务控制语言（COMMIT, ROLLBACK）

数据查询（SELECT）

SELECT语句用于从数据库中检索数据，是最常用的SQL语句。

-- 基本查询
SELECT * FROM students;

-- 条件查询
SELECT name, age FROM students 
WHERE age > 18;

-- 排序查询
SELECT * FROM students 
ORDER BY age DESC;

-- 分组查询
SELECT department, COUNT(*) as count
FROM employees
GROUP BY department
HAVING COUNT(*) > 5;

-- 多表连接查询
SELECT s.name, c.course_name
FROM students s
INNER JOIN courses c ON s.id = c.student_id;

-- 子查询
SELECT * FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);

数据插入、更新、删除

DML语句用于对数据库中的数据进行增删改操作。

-- 插入数据
INSERT INTO students (name, age, email)
VALUES ('张三', 20, 'zhangsan@example.com');

-- 批量插入
INSERT INTO students (name, age)
VALUES ('李四', 22), ('王五', 21);

-- 更新数据
UPDATE students 
SET age = 21, email = 'new@example.com'
WHERE name = '张三';

-- 删除数据
DELETE FROM students 
WHERE age < 18;

-- 清空表（保留结构）
TRUNCATE TABLE students;

数据定义语言（DDL）

DDL用于定义和修改数据库结构，包括表、索引、视图等对象的创建和删除。

-- 创建数据库
CREATE DATABASE school;

-- 创建表
CREATE TABLE students (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    age INT CHECK (age >= 0),
    email VARCHAR(100) UNIQUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 修改表结构
ALTER TABLE students ADD COLUMN phone VARCHAR(20);
ALTER TABLE students DROP COLUMN phone;
ALTER TABLE students MODIFY COLUMN name VARCHAR(100);

-- 创建索引
CREATE INDEX idx_name ON students(name);

-- 删除表
DROP TABLE IF EXISTS students;

模块3：数据库设计（12学时）

实体-关系模型（E-R模型）

E-R模型是概念模型的一种，用于描述现实世界的实体及其联系。

📊 基本要素
  • 实体（Entity）：客观存在并可相互区分的事物
  • 属性（Attribute）：实体所具有的某一特性
  • 联系（Relationship）：实体之间的关联
🔗 联系类型
  • 一对一联系（1:1）
  • 一对多联系（1:N）
  • 多对多联系（M:N）

数据库设计原则

良好的数据库设计应遵循一定的原则，确保数据的完整性、一致性和高效性。

✅ 设计原则
  • 避免数据冗余
  • 保证数据一致性
  • 合理设置主键和外键
  • 选择合适的数据类型
  • 考虑查询性能优化
📋 设计步骤

需求分析 → 概念设计 → 逻辑设计 → 物理设计 → 实施与维护

范式理论

范式是关系数据库规范化的标准，用于消除数据冗余和更新异常。

📐 常用范式
  • 第一范式（1NF）：属性不可再分
  • 第二范式（2NF）：消除非主属性对码的部分依赖
  • 第三范式（3NF）：消除非主属性对码的传递依赖
  • BCNF：消除主属性对码的部分和传递依赖
⚠️ 范式与反范式

过度规范化可能导致查询性能下降，实际设计中需要权衡范式化和性能。

数据库设计实践

通过实际案例学习数据库设计的完整流程。

-- 学生选课系统数据库设计示例

-- 学生表
CREATE TABLE students (
    student_id VARCHAR(20) PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    gender CHAR(1),
    birth_date DATE,
    department_id INT
);

-- 课程表
CREATE TABLE courses (
    course_id VARCHAR(20) PRIMARY KEY,
    course_name VARCHAR(100) NOT NULL,
    credit DECIMAL(3,1),
    teacher_id INT
);

-- 选课表（多对多关系的中间表）
CREATE TABLE enrollments (
    id INT PRIMARY KEY AUTO_INCREMENT,
    student_id VARCHAR(20),
    course_id VARCHAR(20),
    score DECIMAL(5,2),
    enroll_date DATE,
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (course_id) REFERENCES courses(course_id)
);

模块4：数据库管理（12学时）

用户权限管理

数据库用户权限管理确保只有授权用户才能访问和操作数据。

-- 创建用户
CREATE USER 'admin'@'localhost' 
IDENTIFIED BY 'password123';

-- 授予权限
GRANT ALL PRIVILEGES ON *.* 
TO 'admin'@'localhost';

-- 授予特定权限
GRANT SELECT, INSERT, UPDATE 
ON school.students TO 'teacher'@'localhost';

-- 查看用户权限
SHOW GRANTS FOR 'admin'@'localhost';

-- 撤销权限
REVOKE DELETE ON school.* 
FROM 'teacher'@'localhost';

-- 删除用户
DROP USER 'admin'@'localhost';

-- 刷新权限
FLUSH PRIVILEGES;

数据备份与恢复

数据备份是防止数据丢失的重要手段，恢复是备份的逆过程。

💾 备份类型
  • 完全备份：备份整个数据库
  • 增量备份：只备份自上次备份后的变化
  • 差异备份：备份自上次完全备份后的变化
-- 使用mysqldump备份
mysqldump -u root -p school > backup.sql

-- 备份特定表
mysqldump -u root -p school students > students.sql

-- 恢复数据
mysql -u root -p school < backup.sql

数据库性能优化

数据库性能优化是提高系统响应速度和处理能力的关键。

⚡ 优化策略
  • 合理使用索引
  • 优化SQL查询语句
  • 数据库表结构优化
  • 配置参数调优
  • 读写分离与分库分表
-- 查看执行计划
EXPLAIN SELECT * FROM students 
WHERE name = '张三';

-- 创建索引优化查询
CREATE INDEX idx_name ON students(name);

-- 分析表

-- 优化表
OPTIMIZE TABLE students;

数据库安全涉及数据保护、访问控制、审计等多个方面。

🔒 安全措施

模块5：NoSQL数据库（8学时）

NoSQL数据库简介

NoSQL（Not Only SQL）数据库是非关系型数据库，适用于大规模数据存储和处理。

📊 NoSQL类型
  • 键值存储：Redis, Memcached
  • 文档数据库：MongoDB, CouchDB
  • 列族数据库：HBase, Cassandra
  • 图数据库：Neo4j, JanusGraph
✨ NoSQL特点

灵活的数据模型、水平扩展能力、高性能、高可用性、最终一致性。

MongoDB基础

MongoDB是流行的文档数据库，使用BSON格式存储数据，支持丰富的查询语言。

// 插入文档
db.students.insertOne({
    name: "张三",
    age: 20,
    courses: ["数学", "英语"]
});

// 查询文档
db.students.find({ age: { $gt: 18 } });

// 更新文档
db.students.updateOne(
    { name: "张三" },
    { $set: { age: 21 } }
);

// 删除文档
db.students.deleteOne({ name: "张三" });

// 聚合查询
db.students.aggregate([
    { $match: { age: { $gte: 18 } } },
    { $group: { _id: "$department", count: { $sum: 1 } } }
]);

Redis基础

Redis是高性能的键值存储数据库，支持多种数据结构，常用于缓存和会话管理。

# 字符串操作
SET user:1 "张三"
GET user:1
SETEX session:abc 3600 "user_data"

# 哈希操作
HSET user:1 name "张三" age 20
HGET user:1 name
HGETALL user:1

# 列表操作
LPUSH queue:tasks "task1"
RPOP queue:tasks

# 集合操作
SADD tags:article "数据库" "SQL"
SMEMBERS tags:article

# 有序集合
ZADD leaderboard 100 "player1"
ZREVRANGE leaderboard 0 9 WITHSCORES

SQL与NoSQL对比

SQL和NoSQL各有优势，选择合适的数据库类型取决于应用场景。

📊 对比分析
特性 SQL NoSQL
数据模型 关系表 文档/键值等
扩展方式 垂直扩展 水平扩展
事务支持 ACID BASE
适用场景 复杂查询 大数据量
